# Ledger Comment Guide

The `comment` field in `ledger.csv` is an owner-supplied description of the artifact.

It should explain what is inside the file and what audit role the file plays.

## Bad comments

These describe repository maintenance, not file contents:

- `Normalize audit repo wording`
- `Update docs`
- `Fix migration`
- `Add file`
- `Publisher run`
- `Automatic upload`

## Good comments

Daily artifact:

`Daily Orion target file for 2026-06-18. Contains ticker-level target weights intended for the next valid trading session and generated by the approved causal production pipeline.`

Monthly artifact:

`Monthly Orion report for June 2026. Contains the monthly performance summary, drawdown review, exposure statistics, turnover summary, and reconciliation tables for the active publication stream.`

Adhoc artifact:

`Orion non-scheduled change note dated 2026-06-18. Records an important publication-method change, the reason for the change, and the expected effect on future artifacts.`

Adhoc report:

`Orion non-scheduled reconciliation report dated 2026-06-18. Compares private artifacts against public ledger hashes and documents any differences found during review.`

## Required qualities

A good comment should be:

- specific to the file;
- understandable without reading the producer code;
- free of internal experiment version labels unless those labels are part of the official public methodology;
- not a commit message;
- not a marketing claim;
- not a performance claim unless the file itself is a performance report.
